name: page-additions-merge-into-existing-sections
description: When adding content to a live service page, merge it into the existing section on that topic, never add near-duplicate sections or contradict facts already on the page
metadata:
  type: feedback
---

When we propose new content for an existing service page, first map which sections the page already has. New copy goes **inside the matching existing section**. It is never a new section that repeats one that's already there.

- If the page already has a mini-split section, new mini-split content goes in it.
- If the page already has an installation process section, don't add a second one. Add any genuinely new detail to the existing one, or leave it out.
- Keep the "Why Choose" section high and upfront. Additions must not push it down the page.
- New copy must not contradict facts already on the page (e.g. the page says installs take 1 to 3 days, so the new copy can't say 1 to 2), and must not introduce service claims the client doesn't make (e.g. "we handle rebate paperwork", "free quote").
- No em dashes in new content.
- Phone numbers: use the client's main number only, never a CallRail tracking number.

**Why:** feedback on the Vision heat pump installation page additions (2026-10-14). The new sections duplicated existing mini-split and install-process sections, contradicted the page's own install time, claimed rebate paperwork Vision doesn't do, and were full of em dashes. The reviewer had to restructure the page by hand.

**How to apply:** for any page-update doc, list the live H2/H3 outline first and say which existing section each piece of new copy goes into. Use [[page-update-doc-format]] (Current | Replacement). Before sending, check the new copy against the page's existing facts and the client's CLIENT.md "don't do" list. Vision-specific rules are in `clients/Vision/CLIENT.md` section 8.
