# Handoff: Add FAQPage JSON-LD schema to Vision Blog Draft Publisher (Make.com)

## Context

Vision Plumbing & Heating's blog automation (Google Doc → Make.com → WordPress draft) already works: scenario `6209699` "Vision Blog Draft Publisher [TEST - INACTIVE]" was tested 2026-09-09, created draft post 37172 on visionplumbingandheating.com, and the native `<details>/<summary>` FAQ accordion rendered correctly (verified via WordPress REST API — see conversation this file was generated from, or re-check `https://visionplumbingandheating.com/wp-json/wp/v2/posts/37172`).

Client asked about using Elementor's Advanced Accordion widget (Essential Addons) with its built-in FAQ Schema toggle. Investigated: Elementor + Essential Addons IS installed on Vision's site, but wiring Make.com to write Elementor's JSON widget tree is a much bigger job (Elementor stores content in postmeta `_elementor_data`, not the normal post body; that meta isn't REST-writable by default; would need a custom endpoint + reverse-engineered widget JSON schema). Agreed alternative: keep the existing native `<details>` accordion (matches [[blog-automation-faq-accordion-architecture]] memory — no plugin dependency), and just add the `FAQPage` JSON-LD schema block Make.com already has the data to build. Same SEO/rich-result payoff, none of the Elementor risk.

4. Validate the JSON is well-formed (paste into a JSON linter, or Google's Rich Results Test). **Known risk:** the escaping step (module 31) only escapes double quotes (`"` → `\"`). Fine for normal blog copy; worth a note if this gets rolled out to other clients.
