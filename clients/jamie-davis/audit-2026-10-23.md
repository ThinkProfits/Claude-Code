## 2. Critical fixes (do first)

1. **The homepage carries the Calgary page's schema.** The homepage has a second JSON-LD block that is a copy of the Calgary page's graph: `WebPage @id /24-7-towing-calgary/#webpage` plus `Service "Emergency Towing in Calgary, AB"` with `areaServed: Calgary`. This tells Google the homepage is about Calgary towing, which breaks the "Calgary only on the Calgary page" rule and may be one reason Calgary impressions jumped. **Fix:** remove that block from the homepage (likely an Elementor HTML widget pasted from the Calgary page) and replace it with the homepage's own graph. Schema only, no visible change.
2. **No blog exists.** WordPress has 0 published posts; the "Blog" page (ID 186) is a 2022 draft and `/blog/` returns 404. **Fix:** publish a Blog page, set it as the Posts page, add it to the menu (Andrew to approve the label), then publish blogs as the new blog manager approves them.
3. **Stray test post on the wrong site.** Draft post 3973, "This is just a test post from make.com", contains Aloha Life Massage content ("massage after scuba diving in Maui"). The Make.com blog automation pointed at this site at some point. **Fix:** trash it and confirm the Jamie Davis tab in the blog feed sheet maps to the right WordPress connection.
4. **No LocalBusiness schema anywhere.** Every page has only Yoast's Organization/WebSite graph plus a per-page `Service` block. The Yoast graph still uses relative `@id`s (`/#organization`, `url: "/"`), while the hand-authored `Service` blocks point to the absolute `https://www.jamiedavistowing.com/#organization`, so the two never join up. Yoast's site name is "Jamie Davis Motor Truck & Auto Ltd.". **Fix (once the Hope address and legal name are confirmed):** one canonical `AutomotiveBusiness` entity with absolute `@id`, a `department` per location (Hope, Golden, Langley, Chilliwack, Calgary) with its own phone, and `sameAs` links. Also find why Yoast outputs relative URLs (Yoast > Settings > Site representation, and the WordPress Site Address setting).
5. **Privacy policy returns 404.** Page 3 is a 2022 draft. The site collects personal data through Gravity Forms and runs Google Ads, so a live privacy policy is needed. **Fix:** publish one (client to supply or approve the text) and link it in the footer.

## 3. On-page improvements to existing pages

### 3a. Heading clutter on every page (template-level)

Each service and city page carries the same set of H2s:
- "Official BCAA Contractor" **and** "BCAA CONTRACTOR" (two H2s about the same thing)
- "BEST [service] NEAR YOU" / "THE BEST [city] TOWING COMPANY"
- "AS SEEN ON" and "CONTACT US" (footer blocks marked up as H2)
- "Commercial Towing SERVICES" and "Train Recovery SERVICES" repeated on every city page

That leaves 8 to 14 H2s per page, about half of them identical sitewide, which is a strong "templated page" signal and works against the CLIENT.md rule on specific, search-friendly headings. **Proposal:** change the sitewide BCAA, "As Seen On" and "Contact Us" blocks to styled text (not headings), and give each page's remaining H2s page-specific wording. Also drop "best" from headings in line with the no-superlatives rule. Needs Andrew's sign-off because it touches Ads landing pages.
